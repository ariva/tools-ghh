# Settings

ghh persists per-repo UI preferences (view mode, details pane,
pane sizes) across sessions.

## Files

| File | Role |
|------|------|
| `~/.config/ghh/ghh-settings.json` | Global: `defaults` for every repo + one entry per repo under `repos` |
| `<repo>/.ghh-settings.json` | Local override for that repo (flat repo-settings object) |

`$XDG_CONFIG_HOME` is honored for the global file's base directory.

Both files are parsed as **JSON5**: hand-edited files may use comments
(`//`, `/* */`), trailing commas, unquoted keys and single-quoted strings.
The app itself always writes plain pretty-printed JSON (valid JSON5), so
JSON5 syntax survives only in files the app does not rewrite — see
"When settings are saved" below.

## App stamp

The global file carries an `app` block — name, version, build hash and build
date of the build that first wrote the file:

```json5
{
  app: {
    name: "ghh",
    version: "0.4.0",
    build_hash: "221b430",
    build_date: "2026-08-10T15:55:28Z",
  },
  // ...
}
```

It is stamped on start only when missing and **never overwritten** once
present (future upgrade/migration logic will key off it).

`defaults` and `overrides` are seeded as **empty** sections so they are
always visible, and are **read-only for the app**: their contents are
hand-maintained only, never written by the app. When nothing is missing,
start-up does not rewrite the file at all.

## Smart save

The app never stores default values. On quit, a repo entry keeps ONLY what
deviates from the inherited baseline (built-in defaults overlaid with the
global `defaults` section) — plus the identity fields (`short_name`,
`path`, `origin`), which have no defaults. A repo running entirely on
defaults saves as just its identity. Set `defaults.view = "graph"` and a
repo using graph view stores no `view` at all; the same repo switched to
focused stores `view: "focused"` because that now deviates.

## The example file

Next to the global settings file, the app maintains
`~/.config/ghh/ghh-settings.example.json` — a fully commented
reference showing **every** setting with its default value, possible
options and the merge/cap logic explained per field. Copy what you need
into the real files; the example itself configures nothing.

It is recreated on quit **only when the app version or build changed**
(a `// generated by …` stamp on the first line is compared). Hand edits to
it are lost on the next such refresh — it is app-owned.

## Override logic (merge order)

Field-by-field; **latest overrides previous**. Two axes:

1. **File axis** — global settings file → local repo settings file
   (the local `.ghh-settings.json` beats the global file's per-repo entry).
2. **Section axis** — `defaults` → repo-level settings → `overrides`
   (each section beats the one before it).

Combined, the full order is:

1. Built-in defaults
2. Global `defaults`
3. Global `repos["<repo dir name>"]`
4. Local `<repo>/.ghh-settings.json`
5. Global `overrides` — **god level**: beats everything above, including
   the local file. One place to force a setting across all repos:

```json5
{
  defaults: { /* … */ },
  repos: { /* … */ },
  overrides: {
    debug: { log_level: "ERROR" }, // quiet everywhere, no exceptions
  },
}
```

The repo key is the repository directory name (e.g. `ariva-tools`).
`overrides` takes the same fields as any repo entry. The app seeds it as an
empty section (right before `defaults`) so it's always visible; its contents
are hand-maintained only — the app never writes into it.

## Fields

Every field is optional — files only state what they override.

| Field | Type | Meaning |
|-------|------|---------|
| `view` | `"focused" \| "graph" \| "simple"` | Commit list view mode |
| `show_details` | bool | Diff/details pane open on start |
| `debug` | level string or object | Verbosity master knob + debug screen settings. String form: `"INFO"` = minimum trace level. Object form: `{ log_level: "INFO", log_events: true }` — `log_level` (optional, default `INFO`) filters trace rows on the debug screen AND caps the log file's verbosity (one setting to quiet everything; `logs.log_level` may restrict further but never exceed it); `log_events` (optional, default `true`) shows/hides the KEY/SCRN/ACT event rows. Levels `TRACE\|DEBUG\|INFO\|WARN\|ERROR`, case-insensitive. `RUST_LOG`, when set, still caps what is captured at all. On start the app emits one trace per level (trace-check lines) so the active filters are visible at a glance. |
| `splits.list_pct` | 15–85 | Commit list width, % of screen (rest = diff column; shared with staging) |
| `splits.diff_info_pct` | 15–85 | Commit-info height, % of diff column (rest = patch) |
| `splits.details_height` | 3–20 | Details footer height in rows |
| `splits.files_pct` | 15–85 | Width of the Files column, % of diff column (rest = patch). Default 30 |
| `watch_secs` | 0–60 | Seconds between background checks for changes made outside ghh (files, commits, branch switch) while the commit list is shown. `0` = never check (`r` still reloads). Default 2. A check that takes long stretches the wait to ten times its duration |
| `logs` | path string or object | Trace log file. String form = path. Object form: `{ path, enabled, log_level, log_events }` — all optional. `path` default `/tmp/ghh/logs.txt` (`"off"`/`""` disables); tokens: `{REPO}` repo dir name, `{HASH}` stable 8-hex repo-path hash, and date tokens `YYYY` `MM` (month) `DD` `HH` `mm` (minutes) `SS` — e.g. `"/tmp/ghh/{REPO}-{HASH}-{YYYY-MM-DD}.log"`. `enabled` default `true`; `log_level` (optional, default `INFO`) = minimum level written, capped by `debug`'s level; `log_events` default `true` writes app events (key presses, screen changes, actions) into the file regardless of level. CLI `--logs` overrides the path and forces logging on. A fresh file starts on every run. |
| `short_name` | string | Informational: last segment of the origin URL |
| `path` | string | Informational: canonical repo path |
| `origin` | string | Informational: `origin` remote URL |

Splits are stored as percentages (only the footer is absolute rows), so a
saved layout adapts to any terminal size. Out-of-range values are clamped.

## Example

Global `~/.config/ghh/ghh-settings.json`:

```json5
{
  defaults: {
    view: "focused",
    show_details: true,
  },
  repos: {
    "ariva-tools": {
      short_name: "ariva-tools.git",
      path: "/home/arunas/dev/ariva/tools/ariva-tools",
      origin: "git@github.com-personal:ariva/ariva-tools.git",
      show_details: false, // this repo starts with the pane closed
      splits: { list_pct: 30, diff_info_pct: 40, details_height: 8 },
    },
  },
}
```

Local `<repo>/.ghh-settings.json`:

```json5
{
  view: "graph",
  splits: { list_pct: 50 },
}
```

## When settings are saved

On every clean quit the current view, details-pane state and splits are
written to the global file under `repos["<key>"]` (directory created if
missing; entries for other repos are preserved).

The local `.ghh-settings.json` is also rewritten on quit **if it exists**.
Create it the first time with:

```sh
ghh --save-local-settings
```

After that, the file keeps auto-updating without the flag. If you want a
hand-maintained local file with comments that the app never rewrites, don't
run with the flag — settings files are only written for repos the app was
quit in, and only the global entry is unconditional.

**Comment preservation.** Saves are surgical: when nothing changed, the
file is not written at all; when this repo's entry changed, only that
entry's bytes are replaced — JSON5 comments everywhere else (in `defaults`,
`overrides`, around sections, next to other repos) survive every save.
Only comments *inside* this repo's own `repos["<key>"]` entry are lost on
update (that block is machine-written). If the file's shape can't be
parsed for splicing, the app falls back to a full plain-JSON rewrite
(spliced output is validated before writing — a bad splice can never
corrupt the file).

> The local `.ghh-settings.json` is rewritten whole when it changes (it IS
> the machine-written entry), so keep hand-written comments in the global
> file — or don't enable local auto-save.

Add `.ghh-settings.json` to the repo's (or your global) gitignore if it
should stay machine-local; commit it to pin a layout for the whole team.

## Mouse pane resizing

Drag pane borders to resize (saved via the splits above on quit):

- vertical border between commit/file list and the diff column
  (commit list and staging screens share this split)
- horizontal border between Commit Info and the patch pane
- top border of the details footer
